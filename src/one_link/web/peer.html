What this is

This is a browser-as-peer One Link node. Your identity lives in OPFS (origin-private storage); no daemon, no account, no cloud. It's separate from the desktop daemon you may also be running — both are independent peers that can connect to each other once you pair them.

Networking, pairing, chat, and file transfer arrive in subsequent ships. v0.16.0 only provisions identity.

Identity actions

Set a passphrase to wrap this device's keypair with AES-GCM on disk. You'll be prompted to unlock on every visit. Without a passphrase the keypair is plaintext (still origin-private, but readable by anyone with same-user filesystem access).

Reset wipes this device's identity from OPFS. After reset, next reload generates a fresh keypair. You can't recover an old identity from a new one — back it up first via Export if you care about message continuity.

Unlock identity

This device's identity is encrypted. Enter your passphrase to unlock it. We can't recover a forgotten passphrase — if you've lost it, reset and start over.

Connect to mesh

Register with a One Link rendezvous server so other peers can find this device. You can run your own rendezvous (python -m one_link.rendezvous_server) or use a public one. Registration is signed by your local Ed25519 keypair; the server stores presence only, no message content.

Server-observed endpoint

The server saw your connection coming from this address. When other peers look you up, this is what they'll try first.

Direct browser link

Build a direct encrypted browser-to-browser DataChannel. For now, exchange the signal text manually. Every signal is signed by this device identity before the other side trusts it.
