What this is

This is a browser-as-peer One Link node. Your identity lives locally in origin-private browser storage (coordinated OPFS or transactional IndexedDB), not in a One Link cloud account. It is separate from the desktop daemon you may also be running — both are independent peers that can connect once paired.

The browser peer includes identity, signed pairing, rendezvous, direct WebRTC chat, and resumable file upload. Availability still depends on this browser's secure-context and storage support.

Identity actions

Identity private-key material is encrypted on disk with Argon2id and AES-256-GCM. Change the passphrase here to rotate that encryption.

Reset wipes this device's identity. Next time you open the page you'll get a fresh identity, so your laptop won't recognize this phone until you re-pair. Export first if you want to keep the chat history that's already on this phone.

Protect this device identity

Set a passphrase to encrypt this device's identity before it can pair or connect. One Link derives the encryption key with Argon2id; the private identity is never newly written to browser storage in plaintext.

One Link cannot recover this passphrase. Store it in a password manager before continuing.

Unlock identity

This device's identity is encrypted. Enter your passphrase to unlock it. We can't recover a forgotten passphrase — if you've lost it, reset and start over.

Publish signed presence

Publish this browser's signed identity and transport capabilities to a meeting point. You can run your own (python -m one_link.rendezvous_server) or use a public one. This presence record does not make a browser dialable and does not exchange WebRTC signaling; use the QR invitation or Direct browser link below to establish a real session. The meeting point sees presence and network metadata, but not plaintext messages, files, or private keys.

Server-observed HTTP source

Diagnostic only: the meeting point saw the registration request from this address and ephemeral port. It is not a dialable browser endpoint, and peers must not use it as one.

Direct browser link

Build a direct encrypted browser-to-browser DataChannel. For now, exchange the signal text manually. Every signal is signed by this device identity before the other side trusts it.
