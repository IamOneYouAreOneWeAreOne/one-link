## TIER 1 — CRITICAL (exploitable / data-loss / silent compromise)

### T1-A. DR ratchet mutates state BEFORE AEAD verifies (DoS)
File: `double_ratchet.py:549-557` + `:399-440` (`decrypt` → `_dh_ratchet`).
`decrypt()` calls `_dh_ratchet` (rotates own DH keypair, advances root_key, generates new send/recv chains) BEFORE the AEAD decrypt. A forged frame with a random `header.dh` mutates `root_key`, `dh_send`, `dh_send_pub`, `prev_send_n`. Next legitimate send breaks; channel dead. Trivial DoS by any network attacker sending one bogus frame.
Fix: Speculatively compute new state in locals; only commit on AEAD success.

### T1-B. Native transfer fast path: AEAD ignores ratchet, nonce sender-controlled
File: `native_transfer.py:267-273` + `:469`. `encrypt_chunk_bytes`/`decrypt_chunk` derive `nonce = idx.to_bytes(12, "little")` and use `self.shared_secret` (constant per session). `self._ratchet.next_key()` result is **discarded** (`_key, _ = ...`). On channel reopen, `_native_transfer_seed` is cached → new session starts at `_next_send_index=0` with the **same key**. Nonce reuse with ChaCha20-Poly1305 / AES-GCM = keystream recovery + forgery. CATASTROPHIC.
Fix: Use ratchet output as the AEAD key per chunk; bind transcript+epoch into HKDF; persist a strictly-monotonic session epoch counter across reopens.

### T1-C. Receiver trusts wire-supplied `chunk_index`
File: `daemon.py:7800`. `chunk_index = int(msg.get("chunk_index", seq))` — sender picks any 64-bit value. Replay window absent. Combined with T1-B → plaintext recovery via two ciphertexts at same `chunk_index`.
Fix: Enforce strict monotonic per session; reject `<= last_seen` or `>> last_seen`.

### T1-D. `_capability_allowed` fails OPEN in three paths
File: `daemon.py:11428-11429` (state=None → True) + `:11439-11448` (verifier exception → True with counter) + `:11370-11389` (seed-tamper detect exception → fall through to allow).
v0.20.5 audit flagged this; still alive.
Fix: Fail-closed in all three paths; emit one-shot SECURITY warning.

### T1-E. Default-allow-all reversal still active
File: `daemon.py:11440-11449` + `state.py:1439-1449` + `daemon.py:13599-13600`. `policy is None` → allow-all. `_apply_default_capability_policy` leaves `None` when `pair_default_allow_all` unset, and that defaults TRUE. The on-disk + documented "deny-by-default" is fiction.
Fix: Invert default; require explicit opt-in for legacy allow-all.

### T1-F. send_file capability check skipped when `peer_fp_for_policy` is None

### T1-G. FILE_OFFER over QUIC uses empty peer_ed_pub via `_NoopChannel`

## TIER 2 — HIGH (correctness, silent degradation, defense-in-depth)

### T2-A. `recv()` legacy-AEAD fallback unbounded post-DR-activation
File: `channel.py:485-534`. Once DR is active, recv() tries DR then falls back to legacy AEAD on a broad exception list. Bound is "supposed to be one frame" but nothing enforces it. Attacker replays old legacy frames → accepted.
Fix: Hard cap to N=1 legacy frame post-activation; drop+Zeroize legacy keys; track counter.

### T2-B. v1 HELLO signature fallback unconditional
File: `channel.py:763-785`. Logged but accepted. UKS via v1-sig splice between paired peers still live. The `uks_v2_only` CAPS flag hasn't shipped.
Fix: Add env-gated `ONE_LINK_REJECT_V1_HELLO=1` immediately; ship the CAPS flag.

### T2-C. Skipped-key cache eviction is a DoS amplifier
File: `double_ratchet.py:344-353`. FIFO drop of oldest. Attacker sends header with `header.pn = MAX_SKIP_KEYS` → 1000 skipped-key derivations evict all legitimate OOO keys.
Fix: Cap `pn` advancement to remaining lifetime budget per chain.

### T2-D. Chunk-store accepts peer-claimed `chunk_id` without re-hashing
File: `native_transfer.py:439-452`. AEAD tag covers chunk_id-as-AAD but only proves the sender committed to that id, not `id == BLAKE3(plaintext)`. A paired-but-malicious peer can poison your content-addressed store. Other peers asking `has_chunk(id)` will get wrong bytes from your cache.
Fix: After successful decrypt, verify `BLAKE3(plaintext) == chunk_id` before any cache write.

### T2-E. Native chunk seq-mismatch RAISES → kills entire secure channel
File: `daemon.py:7786` (`_handle_file_native_chunk`) + `:7929` (`_handle_file_binary_chunk`). One reordered chunk kills the whole session (all transfers + chat). Legacy FILE_CHUNK handler (5028) ACKs reject + returns — correct.
Fix: Native handlers ACK reject; never raise into channel recv.

### T2-F. CDC source-file mid-transfer mutation raises; receiver hangs
File: `daemon.py:17812`. Sender raises RuntimeError on hash mismatch; receiver never sees a FILE_ABORT. Sidecar resumes a transfer that can never complete.
Fix: Send FILE_ABORT with reason="source_changed" before raise.

### T2-G. `_inbound_live_channels` mutation during iteration
File: `daemon.py:2935-2951` + `:4283`. Recv-loop finally mutates the list while QUIC path reads `_live_inbound[-1]` without snapshot.
Fix: All readers `tuple(self._inbound_live_channels.get(peer_fp) or ())`.

### T2-H. `server.py:13451` broadcast() spawns orphan create_task per WS client

### T2-I. `_quic_dial_lock` is global; one slow peer stalls all dials

### T2-J. Stream `pending_sizes` deque grows on fallback raise

### T2-K. Native session lifecycle: `_native_transfer_seed` derivation race
