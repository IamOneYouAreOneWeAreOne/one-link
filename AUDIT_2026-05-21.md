- **T1-B** Native transfer fast-path AEAD discards ratchet output. Re-evaluated agent claim: within-channel nonces are unique (`_next_send_index` monotonic) and each channel has fresh `transcript_hash` so cross-channel reuse doesn't apply. Real remaining defect is "compromise of `_native_transfer_seed` reveals all chunks of THAT channel" — defense-in-depth, not active exploit. Fix touches every chunk AEAD construction; benchmark first. Re-classified CRITICAL → MEDIUM.
- **T1-H** QUIC accept-loop FIFO race for peer_fp assignment. Real but needs the native `one_link_native.quic` crate to surface peer-fp on accepted Connection. Cross-language design change.
- **T2-C** Skipped-key cache DoS amplifier. Real but the fix touches DR core eviction semantics — high regression risk. The existing `MAX_SKIP_KEYS=1000` bounds the worst case; missing piece is per-chain budget tracking.
- **T2-D** chunk_id re-verify against decrypted plaintext on receive. BLAKE3 per chunk on the hot path = real cost; defer until measured.

## TIER 1 — CRITICAL (exploitable / data-loss / silent compromise)

### T1-A. DR ratchet mutates state BEFORE AEAD verifies (DoS)
File: `double_ratchet.py:549-557` + `:399-440` (`decrypt` → `_dh_ratchet`).
`decrypt()` calls `_dh_ratchet` (rotates own DH keypair, advances root_key, generates new send/recv chains) BEFORE the AEAD decrypt. A forged frame with a random `header.dh` mutates `root_key`, `dh_send`, `dh_send_pub`, `prev_send_n`. Next legitimate send breaks; channel dead. Trivial DoS by any network attacker sending one bogus frame.
Fix: Speculatively compute new state in locals; only commit on AEAD success.

### T1-B. Native transfer fast path: AEAD ignores ratchet, nonce sender-controlled
File: `native_transfer.py:267-273` + `:469`. `encrypt_chunk_bytes`/`decrypt_chunk` derive `nonce = idx.to_bytes(12, "little")` and use `self.shared_secret` (constant per session). `self._ratchet.next_key()` result is **discarded** (`_key, _ = ...`). On channel reopen, `_native_transfer_seed` is cached → new session starts at `_next_send_index=0` with the **same key**. Nonce reuse with ChaCha20-Poly1305 / AES-GCM = keystream recovery + forgery. CATASTROPHIC.
Fix: Use ratchet output as the AEAD key per chunk; bind transcript+epoch into HKDF; persist a strictly-monotonic session epoch counter across reopens.

### T1-C. Receiver trusts wire-supplied `chunk_index`
File: `daemon.py:7800`. `chunk_index = int(msg.get("chunk_index", seq))` — sender picks any 64-bit value. Replay window absent. Combined with T1-B → plaintext recovery via two ciphertexts at same `chunk_index`.
Fix: Enforce strict monotonic per session; reject `<= last_seen` or `>> last_seen`.

### T1-D. `_capability_allowed` fails OPEN in three paths
File: `daemon.py:11428-11429` (state=None → True) + `:11439-11448` (verifier exception → True with counter) + `:11370-11389` (seed-tamper detect exception → fall through to allow).
v0.20.5 audit flagged this; still alive.
Fix: Fail-closed in all three paths; emit one-shot SECURITY warning.

### T1-E. Default-allow-all reversal still active
File: `daemon.py:11440-11449` + `state.py:1439-1449` + `daemon.py:13599-13600`. `policy is None` → allow-all. `_apply_default_capability_policy` leaves `None` when `pair_default_allow_all` unset, and that defaults TRUE. The on-disk + documented "deny-by-default" is fiction.
Fix: Invert default; require explicit opt-in for legacy allow-all.

### T1-F. send_file capability check skipped when `peer_fp_for_policy` is None
File: `daemon.py:16857` + `:17802`. `if peer_fp_for_policy and not self._capability_allowed(...)` — unresolved peer fp bypasses the entire FILES check.
Fix: `if not peer_fp_for_policy: raise RuntimeError("send_file refused: peer fingerprint unresolved")`.

### T1-G. FILE_OFFER over QUIC uses empty peer_ed_pub via `_NoopChannel`
File: `daemon.py:21049` + class-level `peer_ed_pub: bytes = b""` at `:21014`. When QUIC dispatch sends FILE_OFFER through `_on_peer_message(synth_channel, msg)`, `peer_fp = fingerprint_of(channel.peer_ed_pub)` re-derives from empty bytes. Every QUIC FILE_OFFER processed under the same bogus fingerprint. Cap checks pass against a non-existent peer; transfer-ids and IncomingFile buckets collide across all QUIC peers.
Fix: `_NoopChannel.peer_ed_pub = _real_channel.peer_ed_pub if _real_channel else b""`; ideally pass `peer_fp_override` through the dispatch.

### T1-H. `_quic_recent_paired` FIFO race → cross-peer identity confusion
File: `daemon.py:20886-20908`. `is_paired` callback fires on the native pre-handshake thread; accept loop pops front of deque. Two simultaneous handshakes can resolve in any order; the dequeued fp may not match the accepted Connection. Peer A's chunks get processed under Peer B's identity.
Fix: Native crate must surface peer fp on the returned Connection; until then, post-accept TLS-fingerprint re-derive + refuse on mismatch.

### T1-I. `api_file_download` path-traversal: no final resolve check
File: `server.py:12897-12907`. `safe = Path(name).name; safe != name → 400` is a name-equality guard but no `path.resolve().is_relative_to(inbox_dir().resolve())` check. Symlinks inside the inbox can point outside.
Fix: Add resolve+is_relative_to check before serving.

### T1-J. CAPABILITY_GRANT accepted from any channel-authenticated peer
File: `daemon.py:4444-4448` + `cap_store.py:167` (delegation walk). No check that granter is `pinned` or holds the cap being delegated. Stranger/relay/share-link-redeem flows can mint usable grants.
Fix: Reject CAPABILITY_GRANT unless granter is `pinned` AND holds the cap. Delegation walker must filter intermediates by `trust == "pinned"`.

### T1-K. Identity migration race can corrupt `identity.key`
File: `identity.py:367-413`. Two daemons (or one daemon + one CLI tool) loading concurrently both decide to migrate → `_zero_overwrite_file` while the other is mid-load → key file irrecoverable garbage even with correct passphrase if a crash hits between zero-overwrite and rename.
Fix: File lock around the migration block.

### T1-L. Device-invite `/confirm` skips SAS verification
File: `server.py:6157`. SAS computed in `claim` but never required to match before `confirm`. Bearer-token holder gets a self-mesh device cert.
Fix: Require `confirm` to include the SAS the operator read off the screen; compare to `pending["trust_code"]`.

## TIER 2 — HIGH (correctness, silent degradation, defense-in-depth)

### T2-A. `recv()` legacy-AEAD fallback unbounded post-DR-activation
File: `channel.py:485-534`. Once DR is active, recv() tries DR then falls back to legacy AEAD on a broad exception list. Bound is "supposed to be one frame" but nothing enforces it. Attacker replays old legacy frames → accepted.
Fix: Hard cap to N=1 legacy frame post-activation; drop+Zeroize legacy keys; track counter.

### T2-B. v1 HELLO signature fallback unconditional
File: `channel.py:763-785`. Logged but accepted. UKS via v1-sig splice between paired peers still live. The `uks_v2_only` CAPS flag hasn't shipped.
Fix: Add env-gated `ONE_LINK_REJECT_V1_HELLO=1` immediately; ship the CAPS flag.

### T2-C. Skipped-key cache eviction is a DoS amplifier
File: `double_ratchet.py:344-353`. FIFO drop of oldest. Attacker sends header with `header.pn = MAX_SKIP_KEYS` → 1000 skipped-key derivations evict all legitimate OOO keys.
Fix: Cap `pn` advancement to remaining lifetime budget per chain.

### T2-D. Chunk-store accepts peer-claimed `chunk_id` without re-hashing
File: `native_transfer.py:439-452`. AEAD tag covers chunk_id-as-AAD but only proves the sender committed to that id, not `id == BLAKE3(plaintext)`. A paired-but-malicious peer can poison your content-addressed store. Other peers asking `has_chunk(id)` will get wrong bytes from your cache.
Fix: After successful decrypt, verify `BLAKE3(plaintext) == chunk_id` before any cache write.

### T2-E. Native chunk seq-mismatch RAISES → kills entire secure channel
File: `daemon.py:7786` (`_handle_file_native_chunk`) + `:7929` (`_handle_file_binary_chunk`). One reordered chunk kills the whole session (all transfers + chat). Legacy FILE_CHUNK handler (5028) ACKs reject + returns — correct.
Fix: Native handlers ACK reject; never raise into channel recv.

### T2-F. CDC source-file mid-transfer mutation raises; receiver hangs
File: `daemon.py:17812`. Sender raises RuntimeError on hash mismatch; receiver never sees a FILE_ABORT. Sidecar resumes a transfer that can never complete.
Fix: Send FILE_ABORT with reason="source_changed" before raise.

### T2-G. `_inbound_live_channels` mutation during iteration
File: `daemon.py:2935-2951` + `:4283`. Recv-loop finally mutates the list while QUIC path reads `_live_inbound[-1]` without snapshot.
Fix: All readers `tuple(self._inbound_live_channels.get(peer_fp) or ())`.

### T2-H. `server.py:13451` broadcast() spawns orphan create_task per WS client
File: `server.py:13451`. No reference held, no done-callback, exceptions swallowed by loop default handler. OOM after a day of WS-tab activity.
Fix: `self._send_tasks: set[Task]` + `add_done_callback(set.discard)` + try/except inside body.

### T2-I. `_quic_dial_lock` is global; one slow peer stalls all dials
File: `daemon.py:20793`. 10s `connect_blocking` held under single lock.
Fix: Per-peer dial lock (mirror `_outbound_session_create_locks`).

### T2-J. Stream `pending_sizes` deque grows on fallback raise
File: `daemon.py:18047-18068` + `:18138-18153`. Channel close mid-fallback leaks deque.
Fix: try/finally around fallback_quic_batch_to_webrtc.

### T2-K. Native session lifecycle: `_native_transfer_seed` derivation race
File: `channel.py:220-226`. CAPS-receive vs first-chunk send race; both can run before `maybe_activate_ratchet` derives + caches.
Fix: Per-channel lock around derive_native_transfer_secret; or derive eagerly in `initiate`/`respond` at handshake completion.

### T2-L. Test gap: only ONE test asserts on `degradation_events` ring
File: `tests/test_quic_daemon_dial.py:295`. Every daemon_pair file/send test should assert empty events. This is the regression net for the cascading-NULL + DR-wipe class of bugs.
Fix: Add `assert not degradation_events` to every send_file / send / quic_ping integration test.

### T2-M. Many smoke tests substring-grep HTML/source instead of executing
File: 5 browser-peer test files + setup/health-center tests. ~67 tests across 20 files. Don't catch NameError / wiring bugs.
Fix: Run JS through Node where possible; instantiate real aiohttp test client where possible.

### T2-N. Tests that bypass production code wiring
File: `tests/unit/test_daemon_phase_d_wiring.py:22-53` (unbound method + bare object), `tests/unit/test_native_transfer_cutover.py:299-339` (env-flag tests just read os.environ), `tests/test_two_device_soak.py:245-257` (`assert True`).
Fix: Real Daemon-shaped fixture, drive production call sites end-to-end, delete tautological tests.

### T2-O. Server CSRF not defended; cookie-based POST/DELETE
File: `server.py:1848` (`_guarded`). No Origin allowlist check. Malicious localhost page can ride the cookie.
Fix: Require either `Authorization: Bearer` OR custom `X-One-Link-CSRF` header mirroring cookie on non-GET routes.

### T2-P. ENDPOINT_UPDATE host poisoning via unverified `quic_port`
File: `daemon.py:14605-14619`. Stashed immediately on receipt from pinned peer; no verification before next outbound dial uses it.
Fix: Schedule verify dial before stashing.

### T2-Q. `_quic_outbound` overwritten without close (FD leak)
File: `daemon.py:20827`. Entry replaced without closing prior Connection.
Fix: Close before overwrite; treat inbound+outbound as paired.

### T2-R. state.db is world-readable on POSIX by default
File: `paths.py:142-146` + `state.py:421`. DR chain keys, message bodies, group sender keys all in plaintext, mode inherits umask.
Fix: chmod 0o600 state.db; chmod 0o700 data_dir.

### T2-S. Cap root key has no rotation API
File: `cap_root_key.py`. If leaked, every future macaroon is forgeable. Mnemonic-restore mints fresh but no in-place rotation.
Fix: `rotate_cap_root_key()` + `cap_root.old.key` grace window.
