# Async/Concurrency Audit — `One_link/src/one_link/daemon.py` + `server.py`

**Scope:** 21,276-line daemon, 13,635-line server. Inventoried 23 `while True:` background loops, 24 `asyncio.create_task` sites, 6 `asyncio.Lock` classes (5 dict-keyed, 1 global), 220+ `contextlib.suppress(Exception)` blocks, full `stop()` teardown.

## Top 15 findings (severity-ordered)

1. **CRITICAL — `server.py:13451`** — `broadcast()` fires `asyncio.create_task(ws.send_json(event))` per event per WS client with **no reference held, no done-callback, no exception swallow**. Every msg/presence/transfer event spawns N orphan tasks. **Impact:** OOM after a day of WS-tab activity; CPython warns "Task was destroyed but it is pending"; failed sends raise into the loop default handler. **Fix:** track in `self._send_tasks: set[Task]`, add `task.add_done_callback(self._send_tasks.discard)`, wrap body in `try/except`.

2. **CRITICAL — `daemon.py:20793`** — `_quic_dial_lock` is a **single global lock** for all per-peer QUIC dials; `await asyncio.to_thread(connect_blocking, ..., 10_000)` is held inside it. One slow/dead peer stalls all other QUIC dials for up to 10s. **Fix:** mirror `_outbound_session_create_locks` pattern — one lock per `peer_fp`.

3. **HIGH — `daemon.py:1435,1563,16427`** — `_outbound_session_create_locks`, `_outbox_flush_locks`, `_resume_lock_dict` are dicts of `asyncio.Lock` keyed by `peer_fp` that are **never pruned**. Every peer ever paired or attempted contributes a permanent Lock. **Impact:** unbounded memory growth proportional to lifetime peer-set; per-peer Lock = ~200 B + each lock attaches futures briefly. **Fix:** prune in `_drop_outbound_session` and on peer-revoke.

4. **HIGH — `daemon.py:21087 stop()`** — `_endpoint_verify_tasks` (sets at line 1568) and `_quic_inbound_tasks` (line 20856) are **never cancelled/awaited in `stop()`**. Tests + dev hot-reload leak running tasks; in-flight TCP probes survive teardown and write to closed state. **Fix:** iterate and cancel both sets after closing endpoints; gather with `return_exceptions=True`.

5. **HIGH — `daemon.py:8514`** — `asyncio.create_task(_runner())` inside `_finish_cdc_file_in_background` — orphan task, no set, no callback. Any exception escapes only as a warning log; if the loop is closing, "task destroyed but pending" warning fires. Same anti-pattern at **4534** (`send_file`), **3185** (`_execute_self_mesh_send`), **14614/14630/14846** (`_reply_endpoint_update_to_peer`, `_verify_and_promote_endpoint`), **18533** (`_control_shutdown`), **19058** (`broadcast_endpoint_to_paired`), **18665** (`send_file` batch — at least this one is `await asyncio.gather(*tasks)`). **Fix:** centralize via `self._track(create_task(...))`.

6. **HIGH — `daemon.py:13554` + `13609`** — `_courier_monitor_task` (in `server.py`) — start logs but stop only does `await self._courier_monitor_task` without `(asyncio.CancelledError, Exception)` in except. If the loop body raised something other than `CancelledError`, awaiting re-raises and propagates through `stop()`.

7. **MEDIUM — `daemon.py:20114-20117`** — Same-port QUIC rebind cancels `_quic_accept_task` and creates a new one **without awaiting the cancelled task**. Old accept_loop is still running its `to_thread(accept_blocking, 5000)` for up to 5s; when it resumes it writes to the now-replaced `_quic_inbound_tasks` set. Two accept loops can momentarily race. **Fix:** `await prior_task` (with timeout) before reassigning.

8. **MEDIUM — `daemon.py:20945 _quic_inbound_frame_loop`** — `while True:` over `to_thread(recv_frame_blocking, 30_000)`. Exception path at 20952 `return`s without removing `peer_fp` from `_quic_inbound` — `finally` at 21084 only pops if `self._quic_inbound.get(peer_fp) is conn`. A reconnect between exception and `finally` is fine, but the `return` short-circuit happens **before** the `finally` runs (so OK actually — `finally` still runs on return). However the early `return` paths swallow exception then loop ends; verified OK.

9. **MEDIUM — `daemon.py:2271 _dm_reaper_loop`** — re-raises `CancelledError` correctly, but `except Exception:` swallows DB-level errors that leave the reaper running against a closed state. **Impact:** post-`state.close()` ticks log warnings forever if `stop()` cancels reaper after state close. **Fix:** check `self.state is None` *after* sleep; break.

10. **MEDIUM — `daemon.py:20862 _quic_accept_loop`** — `except Exception as e: ... continue` with `await asyncio.sleep(0.5)`. Endpoint permanently broken (e.g. fd closed) → infinite tight-ish loop logging "QUIC accept loop error" every 0.5s. **Fix:** detect repeated identical errors → break out, log once, mark endpoint dead.

11. **MEDIUM — `daemon.py:13759-13776`** — `_outbound_session_create_locks[peer_fp]` is held across `_probe_outbound_session(existing)` which itself acquires `sess.lock`. Lock ordering = **create_lock → sess.lock**. Outside the create path, `send_to` (13898) and `_probe` (13680) both take `sess.lock` after `_get_outbound_session` returns (lock released). Safe today, but adding any code that takes `create_lock` while holding `sess.lock` would deadlock. **Fix:** document the order in a comment; assert ordering in tests.

12. **MEDIUM — `daemon.py:19099-19104`** — `for fp, conn in self._quic_outbound.items():` (no `list()` wrap) inside the control-socket `quic_status` handler. The handler is `async` and the dict body doesn't await, but `_quic_connection_alive(conn)` is a method call; if it ever becomes async, `RuntimeError: dictionary changed size during iteration` returns from any concurrent dial. **Fix:** wrap in `list(...)` defensively (cheap, idiomatic everywhere else in this file).

13. **MEDIUM — `daemon.py:9858 happy_eyeballs`** — `tasks = [create_task(_attempt(...))]`; on first-winner it cancels pending but doesn't `await` cancellations. Cancelled tasks may finish writing to `writer` / opening sockets between the cancel and GC. **Impact:** brief FD leak per parallel-dial. **Fix:** `await asyncio.gather(*pending, return_exceptions=True)` after picking a winner.

14. **LOW — `daemon.py:19057`** — `with contextlib.suppress(Exception): asyncio.create_task(...)`. `create_task()` itself only raises if no event loop is running; suppression here masks a programming error during shutdown. Same shape at **20320, 20323**. **Fix:** check `loop.is_running()` once at top instead of suppressing per-call.

15. **LOW — `daemon.py:20283 _prune_loop`** — body wraps every sub-tick in `contextlib.suppress(Exception)`. If `_prune_chunk_cache` raises a `MemoryError` (BaseException-derived but `Exception` for OOM in 3.11), suppression swallows it silently and the loop continues with corrupted state. The `except asyncio.CancelledError: pass` outside is correct, but inner `suppress(Exception)` hides real bugs. **Fix:** log the suppressed exception type at `WARNING` level rather than swallowing wholly silent.

## Patterns that are *correct* (worth preserving)

- `_endpoint_verify_tasks.add(task); task.add_done_callback(set.discard)` (lines 14640, 14858) is the textbook pattern — should be templatized and used everywhere `create_task` appears.
- All 23 `while True:` loops checked do return/raise on `CancelledError` (often via `await asyncio.sleep` re-raise); none silently survive cancel.
- `Python 3.11+` requirement (`pyproject.toml:5`) means `CancelledError` is `BaseException`, so the 220+ `suppress(Exception)` blocks do NOT swallow cancellation (they would on 3.7).
- Lock dicts are populated lazily under the GIL-safe `if None: create` pattern; no double-init race in CPython.
